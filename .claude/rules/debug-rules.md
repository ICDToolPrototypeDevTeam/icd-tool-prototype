# Claude Code 调试规则

本文档用于规定 Claude Code 在 **ICD工具原型** 项目中的问题定位、修复和验证规则。

## 1. 基本原则

Debug 任务必须遵守以下原则：

1. 先定位问题，再修改代码；
2. 先说明原因分析和修复方案，再执行修改；
3. 优先采用最小修复方案；
4. 不得在 Debug 过程中顺手重构；
5. 不得修改与问题无关的文件；
6. 不得为了修复局部问题引入新的功能设计；
7. 修复完成后必须给出验证方式；
8. 如问题尚未定位，应明确说明“尚未定位”。

## 2. Debug 前必须确认的信息

开始 Debug 前，应尽量确认问题现象、复现方式、报错信息、影响模块和关联 Issue；信息不足时不得猜测式修改。

## 3. Debug 任务读取文件规则

Debug 任务应优先读取以下文件：

```text
CLAUDE.md
.claude/rules/context-rules.md
.claude/rules/debug-rules.md
docs/development/debug-log.md
用户提供的报错信息
与问题直接相关的代码文件
```

不得因为 Debug 任务默认读取整个工程。

不得默认读取以下目录：

```text
docs/knowledge/
backend/output/
backend/app/output/
node_modules/
.venv/
frontend/dist/
frontend/build/
大型 Word、Excel、PDF 样例文件
运行时生成的输出文件
```

如确需读取，应先说明原因。

## 4. 修改前必须输出的内容

在执行任何 Debug 修改前，Claude Code 应先输出以下内容：

```text
问题现象：
复现方式：
相关文件：
初步原因分析：
最小修复方案：
计划修改文件：
不修改范围：
验证命令：
```

用户确认后，再进行修改。

## 5. 最小修改原则

Debug 修改应遵守最小修改原则。

允许的修改包括：

1. 修正明确定位的代码错误；
2. 修正明确定位的配置错误；
3. 补充必要的异常处理；
4. 修正错误的字段名、路径、类型或调用方式；
5. 修正导致构建、运行或测试失败的直接原因。

不允许的修改包括：

1. 顺手重构模块；
2. 顺手调整目录结构；
3. 顺手修改 UI 样式；
4. 顺手修改 API 契约；
5. 顺手新增业务功能；
6. 顺手优化无关代码；
7. 顺手改动 Prompt、Agent 或评分规则，除非问题直接与其相关。

## 6. 问题类型与优先检查位置

| 问题类型 | 优先检查 |
|---|---|
| 前端问题 | 浏览器控制台、网络请求、`frontend/src/`、`frontend/src/api/` |
| 后端接口问题 | 后端日志、`main.py`、`models.py`、`docs/architecture/api.md` |
| 主流程问题 | `pipeline.py`、任务状态、统一分析输入包 |
| 文件解析问题 | `parsers/`、输入文件类型、解析结果来源信息 |
| 多智能体问题 | `crew/`、`prompts/`、`skills/`、模型返回格式 |
| 评分问题 | `scoring/`、评分输入、评分公式、兜底规则 |
| DOCX 输出问题 | `docx/`、输出目录、下载接口、文件路径 |
| Docker/环境问题 | `docker-compose.yml`、Dockerfile、`.env`、端口、容器日志 |

## 7. 验证规则

Debug 修复完成后，应给出明确验证方式。

验证方式可包括：

1. 重新运行构建命令；
2. 重新启动服务；
3. 重新调用接口；
4. 重新上传样例文件；
5. 检查任务状态；
6. 检查输出文件是否生成；
7. 检查前端页面是否正常展示；
8. 检查日志是否不再报错。

如果无法实际验证，应明确说明：

```text
尚未验证，原因是：
```

不得声称未执行过的验证已经通过。

## 8. Debug 记录规则

以下情况应更新 `docs/development/debug-log.md`：

1. 问题影响主要功能；
2. 问题定位过程较复杂；
3. 问题可能后续重复出现；
4. 问题涉及架构、API、任务状态或输出文件；
5. 问题修复后需要保留复盘记录。

简单拼写、格式或明显小错误可不记录，但任务完成汇报中应说明已修复。

## 9. Debug 完成汇报要求

Debug 完成后，Claude Code 应汇报：

```text
问题原因：
修改内容：
修改文件：
验证命令：
验证结果：
是否更新 debug-log.md：
遗留问题：
```

如果没有修改文件，应明确说明“未修改文件”。

如果问题未解决，应明确说明当前定位结果和下一步建议。
