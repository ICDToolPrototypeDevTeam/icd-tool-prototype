## 背景

工具部署在内网 / VPN 环境，最终约 40–50 个账号、按 20 个并发设计。此前所有任务、历史结果、下载链接和运行时设置都是全局共享的：任何能访问页面的人都能查看、下载、继续或删除其他人的分析结果，也能修改全局模型设置和 HLR 样式。

同时存在一个必须一并修复的安全问题：`main.py` 的 SPA 静态兜底路由把请求路径直接拼到静态目录下，没有限制解析后的位置。服务器部署中静态目录是 `/app/static`、产物目录是 `/app/output`，请求 `/../output/v4/<job_id>/output/...`（含 `%2e%2e` 编码形式）可绕过 API 直接读取他人产物；桌面打包形态还可能读到 `../.env`。

本阶段只解决“谁能登录、谁能看哪些任务、谁能改全局配置”，不改变分析管线、产物生成方式和产物存储位置。

## 决策

### D1：MongoDB 使用独立容器，只存账号

MongoDB 作为 compose 中的独立服务运行，不塞进后端容器：

- 镜像固定为 `mongo:7.0.14`（可用 `MONGO_IMAGE` 覆盖）；仅用命名卷 `mongo_data` 持久化；
- 开发编排只绑定 `127.0.0.1:27017` 方便本机调试；服务器编排**不映射宿主端口**，只允许后端容器通过 compose 内部网络访问；
- 服务器编排设 `pull_policy: never`，离线交付包必须包含 `mongo-image.tar.gz`，服务器先 `docker load`；
- healthcheck 通过后后端才启动（`depends_on: condition: service_healthy`）；
- 本阶段不启用 Mongo 认证，依赖 Docker 网络隔离；如后续合规要求，再增加 Mongo 账号；
- 后端启动时 Mongo 不可达即启动失败；运行中失联时受保护接口返回 503，不返回 500 堆栈。

MongoDB 在**本阶段只存账号**，不存任务、不存分析产物、不存设置与 HLR 样式。任务仍以内存 `JobManager` + `job.json` manifest 管理，产物仍落 `backend/output/v4/{job_id}/`。

### D2：认证采用 fastapi-users + Beanie

后端新增 `backend/app/auth/`，使用 `fastapi-users[beanie,jwt]==13.0.0`、`beanie==1.26.0`、`motor==3.6.0`，提供用户模型、密码哈希、`UserManager`、登录 / 登出路由以及 `current_user` / `current_admin` 依赖。

- 只挂载登录 / 登出路由；注册、邮箱验证、找回密码路由不挂载；
- 账号由管理员通过自定义 `/api/v4/admin/users*` 创建、重置密码、禁用 / 启用；
- 不升级 FastAPI，新增依赖版本在 `requirements.txt` 中锁定。

### D3：登录状态使用 HttpOnly Cookie（JWT）

现有前端大量使用 `<a href>` 直接下载产物，并用 `window.open` 新标签页查看 `reverse_matches.json`。如果改用 `Authorization` 头，这些直接链接不会携带 Token，需要把全部下载 / 查看改成 fetch + blob，改动大且容易漏。

因此采用 Cookie 传输：

- 登录成功后由 `CookieTransport` 下发 HttpOnly JWT Cookie；
- 浏览器同源请求自动携带，现有下载链接、新标签页、轮询无需改造；
- Cookie 参数：`HttpOnly=true`、`SameSite=Lax`、`Path=/`、有效期默认 8 小时（`AUTH_TOKEN_TTL_SECONDS=28800`）、Cookie 名 `AUTH_COOKIE_NAME=icd_auth`；
- `Secure` 由 `AUTH_COOKIE_SECURE` 控制，内网 HTTP 默认关闭；启用 TLS 后改为 `1`；
- 登出清 Cookie；本阶段不做刷新 Token，JWT 过期后需重新登录；
- `SameSite=Lax` + 同源部署下跨站 POST 不携带 Cookie，本阶段不额外实现 CSRF Token。

### D4：登录标识使用用户名

账号是“用户名 + 密码”，不使用邮箱：

- fastapi-users 的用户模型以 `email` 字段承载登录标识，本项目把 `email` 当作“用户名”存储，API 与前端只暴露 `username`；
- 自定义 UserCreate / UserUpdate schema，把 `email` 放宽为普通字符串，避免 `EmailStr` 拒绝非邮箱格式；
- 用户名统一转小写存储与比较，因此登录大小写不敏感、不会产生大小写重复账号；
- 用户名创建后不可修改；显示名、部门等字段本阶段不做。

### D5：任务归属写入 Job 与 manifest

不引入独立的“任务-用户”映射表：

- `Job` 增加 `owner_id`（用户 `_id` 的字符串形式）与 `owner_username`（冗余展示用）；
- `job.json` manifest 增加同名顶层字段；
- 创建任务时从当前登录用户写入；续跑沿用原归属，不允许改归属；
- 旧 manifest 没有归属字段 → 归属为空，只对管理员可见；
- CLI 创建的任务同样没有归属，仅管理员可通过 API 访问；
- 权限判断只认 `owner_id`；`owner_username` 仅用于管理员列表展示，不参与鉴权。

### D6：管理员与普通用户的权限边界

权限按“公开 / 登录 / 管理员”三档划分：

- 公开：`GET /api/v4/health`、`POST /api/v4/auth/login`；
- 登录用户：登出 / 当前用户、创建正反向任务、本人任务的列表 / 状态 / 结果 / 日志 / 日志下载 / 产物下载 / 匹配中间产物查看 / 继续 / 放弃 / 终止、本人历史、HLR 样式列表 / 扫描 / 试解析；
- 管理员：全部任务与历史的查看、下载、继续、终止、删除；`/admin/users*`；`GET/PUT /settings`；HLR 样式新建 / 更新 / 删除。

完整权限矩阵与错误语义只在 `docs/architecture/api.md` 第 17 节维护，本 ADR 不重复展开。按 `job_id` 访问的任务级接口统一由 `app/auth/access.py` 的 `require_job_access()` / `ensure_owner()` 校验；任务 / 历史列表按 `owner_id` 过滤，不在各路由重复拼 owner 判断。

### D7：任务级越权统一返回 404

- 未登录 → 401；
- 已登录但访问他人任务、未归属任务或不存在任务 → 404（不暴露任务是否存在，避免用 404/403 差异探测他人任务）；
- 普通用户访问管理员接口 → 403；
- 管理员放行全部任务；
- Mongo 不可用 → 503 `{"detail": "database unavailable"}`。

### D8：静态兜底与文档端点一并收紧

- SPA 兜底解析路径时先 `unquote` 解码，拒绝任何 `..` 段，再用 `resolve()` + `relative_to()` 确认解析结果仍位于静态目录内；否则返回 404，不回落 `index.html`（不做路径纠正），保证静态目录外文件不可达；
- `/api/*` 未匹配路由不进入 SPA 兜底，返回 JSON 404；
- 静态目录本身可公开（登录页需要），但不得通过它暴露静态目录以外的文件；
- `/docs`、`/redoc`、`/openapi.json` 由 `ICD_DOCS_ENABLED` 控制：开发默认开启，服务器编排设 `0` 关闭。

### D9：管理员初始化与账号生命周期

- 首次启动时若用户集合为空，从 `ICD_ADMIN_USERNAME` / `ICD_ADMIN_PASSWORD` 创建初始管理员；
- 未配置这两个变量且用户集合为空 → 启动失败并给出明确日志；不允许写死默认密码；
- 用户集合非空时忽略初始化变量，不会重置已有账号；
- 管理员可创建账号（用户名 + 初始密码 + 是否管理员）、重置密码（无需旧密码）、禁用 / 启用、设置 / 取消管理员；
- 不删除账号：删除会让其历史任务失去归属；只支持禁用；
- 必须始终保留至少一个活跃管理员：禁用或降级最后一个活跃管理员 → 409；
- 唯一管理员忘记密码时，按部署说明中的 `mongosh` 命令手工重置。

### D10：桌面版暂停、阶段 B 延后

- Windows 桌面打包（PyInstaller 单目录）本阶段**暂停交付**，只保证内网服务器 Docker 部署；后续如需恢复，需单独设计内嵌 Mongo 或桌面鉴权模式；
- 任务与分析产物入库（阶段 B，任务 / 产物迁入数据库）不在本阶段范围，另行设计；
- 本阶段不改变正向管线代码树，不改变产物生成与落盘方式。

## 原因

1. 登录与隔离是内网多账号使用的前置条件；不解决则任何访问者都能交叉查看和删除他人结果；
2. Mongo 独立容器 + 命名卷把账号数据与产物文件解耦，容器重建不丢账号，回滚旧版本时也不影响 `output/`；
3. fastapi-users 提供成熟的密码哈希、用户管理和认证依赖，避免自研认证的安全细节；
4. Cookie 传输让现有 `<a href>` 下载与新标签页查看零改造，回归面最小；
5. 归属字段随 Job / manifest 落盘，不引入额外映射表，旧任务自然按“无归属”降级为管理员可见；
6. 统一 404 语义与统一访问校验函数避免各接口出现不一致的越权判断；
7. 静态兜底收紧与登录隔离必须同批验收，否则 API 鉴权可以被静态路径绕过。

## 影响

- **后端**：新增 `backend/app/auth/`（`config` / `db` / `models` / `schemas` / `manager` / `backend` / `seed` / `deps` / `router` / `access`）；`main.py` 在 lifespan 初始化 Mongo、播种管理员、收紧静态兜底并支持 `ICD_DOCS_ENABLED`；`job_manager.py` 增加归属字段；各 V4 路由增加登录 / 管理员依赖与任务归属校验；`/health` 增加 `database` 状态。
- **前端**：新增登录页、`AuthContext`、`RequireAuth` / `RequireAdmin` 路由守卫、管理员用户管理页；顶栏显示当前用户与退出；非管理员隐藏模型设置、用户管理、历史删除、HLR 样式写入入口；管理员任务 / 历史列表显示“所属账号”列。
- **部署**：`docker-compose.yml` 与 `docker-compose.server.yml` 增加 `mongo` 服务、命名卷与 healthcheck；交付包增加 MongoDB 镜像归档；`backend/.env` 增加 Mongo 与认证变量。服务器内存预算必须为 Mongo 预留，默认上限 1 GB；部署说明给出计算方式，物理内存 < 8 GB 需重新评估，1–2 GB 机器不满足本方案要求。
- **兼容性**：旧任务目录 / CLI 任务无归属，只对管理员可见；升级后现有未登录调用（除 `/health` 与登录）一律 401，这是预期行为变化；回滚代码即可恢复无登录状态，Mongo 容器与卷可保留。
- **已知限制**：内网 HTTP 下密码与 Cookie 明文传输，接受现状并在文档中提示；重置密码不会使已签发的旧 JWT 立即失效（最长 8 小时自然过期）；不实现登录失败锁定 / 验证码 / CSRF Token；不删除账号；Mongo 是登录硬依赖。
- **文档**：本 ADR、`docs/project/scope.md`、`docs/project/workflow.md`、`docs/architecture/current-architecture.md`、`docs/architecture/api.md`、`README.md`、`CHANGELOG.md`、`docs/development/development-log.md`、`docs/testing/服务器部署验收清单.md` 与 `部署说明.md`。

## 替代方案

| 方案 | 不选择理由 |
| --- | --- |
| 继续全局共享，只在部署层用网络隔离 | 无法满足按账号隔离任务与结果的要求；同一网段内任何人仍可交叉访问 |
| 把 MongoDB 与后端塞进同一容器 | 升级 / 备份 / 资源限制耦合；Mongo 进程异常会影响 API；镜像体积与启动顺序更难管理 |
| 使用 Bearer Token + `Authorization` 头 | 现有下载链接与新标签页不会携带 Token，需要全面改成 fetch + blob，改动大、易漏 |
| 自研用户表与密码哈希 | 需要自行处理哈希、时序、会话与依赖注入，安全风险和维护成本更高 |
| 用邮箱作为登录标识 | 现场账号无邮箱，且 `EmailStr` 会拒绝非邮箱格式，需额外放宽与展示映射 |
| 独立的“任务-用户”映射表 | 需要与任务状态双写并处理旧任务迁移；归属随 Job / manifest 落盘更简单、可恢复 |
| 越权返回 403 | 403/404 差异可被用来探测他人任务是否存在；统一 404 不暴露存在性 |
| 本阶段同时做产物入库（阶段 B）/ 恢复桌面版 | 扩大改动面与验证成本；当前目标是先完成登录与账号隔离，产物存储方式不变 |
