## 背景

V4 反向管线 Step 5 Review Agent 当前采用 **3 星体系**（full→3★，majority→2★，split→1★），
由 review LLM 直接输出 `star_rating` 字段。

实践发现：

1. 3 档粒度过粗，「全一致但 evidence 弱」（如 3 个 provider 都给 covered 但 analysis 笼统）
   与「全一致且 evidence 强」（互相引用具体 ICD 字段）无法区分
2. 一星复查（Step 5.5）触发面窄，仅 1★ 触发；2★（多数一致但有具体反对意见）
   缺失复查机会
3. LLM 直接输出 `star_rating` 存在不稳定性，不同批次评分漂移

## 决策

引入 **5 星评价体系**，核心变更：

1. **5 档星评**：在原 3 档基础上引入 4★ 与 2★ 中间档
2. **evidence_alignment 字段**：review LLM 新增自评字段（strong/moderate/weak），
   后端按 `(agreement_level, evidence_alignment)` 二维映射，避免 LLM 直接选星
3. **复查触发扩展**：从 `star_rating == 1` 扩展到 `star_rating ∈ {1, 2}`
4. **breaking change**：老 `star_distribution` 字段从 3 键扩到 5 键；
   `ConsensusResult.star_rating` 类型从 1-3 扩展到 1-5

### 5 档映射规则

| 星级 | agreement_level | evidence_alignment | final_coverage_status | 老 3★ 映射 |
|---|---|---|---|---|
| 5★ | full | strong | majority coverage_status | 老 3★ 高 evidence |
| 4★ | full | moderate / weak | majority coverage_status | 老 3★ 低 evidence |
| 3★ | majority | strong / moderate | majority coverage_status | 老 2★ 高 evidence |
| 2★ | majority | weak | 待确认 | 老 2★ 低 evidence |
| 1★ | split / single_source / no_consensus | (any) | 待确认 | 老 1★（不变） |

### evidence_alignment 判定

- **strong**：至少 2 个 provider 的 analysis 文本**明确引用了对方提到的具体 ICD 字段**（Label / DataFormatType / 方向 / 单位 / 范围 / BitOffset 等）
- **moderate**：3 provider 结论一致，但只有 1 个有具体 ICD 引用
- **weak**：analysis 文本笼统，无具体 ICD 字段引用

### 复查升星路径

| 当前 | 复查后可达 | 路径逻辑 |
|---|---|---|
| 1★ | 2★ | peer-aware 后，原本 split 的 3 provider 形成 majority |
| 2★ | 3★ | provider 重新审视「反对方 evidence」→ 发现对方引用不充分 |
| 4★ | 5★ | **理论路径，非主动机制** —— 复查触发集合仅 `{1, 2}`，4★ 不进入 re-review；4★ → 5★ 仅在自然多次重判时概率性发生（详见「待验证」第 4 条） |

### 降级 cap（不变）

| 存活 provider | cap |
|---|---|
| 0 | 1★ + no_consensus + 待确认 |
| 1 | ≤1★ |
| 2 | ≤2★ |
| 3 | 不限制（不加 confidence cap） |

## 原因

- **5 档粒度**：区分「全一致但 evidence 弱」（4★）与「全一致 evidence 强」（5★），
  让人工复核时能识别「方向一致但依据不足」的 case
- **evidence_alignment 维度**：避免 confidence 数值阈值的不稳定性（LLM 给 confidence 0.85/0.6
  的标准不明确），改用 evidence 文本特征
- **复查范围扩展**：2★→3★ 是有实操价值的升星路径（peer-aware 让反对方 evidence 被重新审视）；
  1★→2★、2★→3★ 实证有效（用例6：1★ → 3★、2★ → 5★）
- **4★ 不触发 re-review（设计选择）**：4★ 已是 full agreement，触发 peer-aware 复查的
  边际收益小但 LLM 调用成本约 +33%；4★ → 5★ 留作理论路径，靠自然多次重判概率性发生，
  4★ 比例本身就是 evidence_alignment 判定质量的可观测信号
- **后端计算星档**：LLM 只输出 agreement + evidence，后端按映射规则算 star，避免 LLM 评分漂移

## 替代方案

### 方案 A：保留 3 星体系，仅扩展 final_coverage_status 维度

3 档粒度粗，无法区分「全一致 + evidence 弱」与「全一致 + evidence 强」。
**否决**。

### 方案 B：5 星 + confidence 数值阈值（confidence 0.85 强 / 0.60 弱）

LLM 给 confidence 的标准不明确；用户明确指出「confidence 是 AI 给的，给分规则不明确」。
**否决**。

### 方案 C：5 星 + evidence 文本特征（采用）

evidence_alignment 判定基于 analysis 文本是否引用具体 ICD 字段，
比 confidence 数值阈值客观，且可由 prompt 中的 few-shot 示例稳定指导。
**采用**。

# 备注

- 老 3 星 → 新 5 星映射关系仅供人工对照理解，不在代码中做迁移映射（consensus_results.json 不存在跨版本兼容，老数据需重新跑）
- 5★ 与 4★ 的边界主要靠 evidence_alignment 判定，prompt 中需要 few-shot 示例稳定 LLM 输出
- 后续根据真实 LLM 跑出来的 5 档分布，可能需要调整 prompt 提示或 evidence 判定标准
- **4★ → 5★ 路径澄清**：本表格列为「理论路径，非主动机制」。复查触发集合仅 `{1, 2}`，
  4★ 不进入 re-review。如果后续生产环境 4★ 比例持续偏高（>20%），可考虑：
  (a) 优化 consensus prompt 让 evidence_alignment 判定更精准，或
  (b) 新增轻量级「evidence 补充」机制（仅让 provider 重写 analysis，不重跑整个 judgment）
- 实证记录见 `docs/development/development-log.md` 的「2026-08-23 复查升星路径实证」条
