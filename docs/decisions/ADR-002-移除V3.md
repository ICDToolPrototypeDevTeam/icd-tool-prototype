# ADR-002 移除 V3 旧版代码

| 项目 | 内容 |
| --- | --- |
| 状态 | **Accepted** |
| 生效范围 | 后端 + 前端 + 依赖 + 文档 |
| 提议日期 | 2026-08-20 |
| 关联 ADR | 部分取代 ADR-001（D2、D8 及 D1 中「暂不删 V3」部分） |

---

## 背景

V4.0 反向管线自「V4.0 后端工程化集成」Issue 落地以来已稳定运行；前端 `App.tsx` 已完全切换至 V4 界面与 `/api/v4` 接口，V3 组件不再被引用。V3 旧代码（CrewAI chunk-level 正向管线、`/api` 路由、顶层 `crew/` / `scoring/` / `merge/` / `docx/` / `parsers/` / `llm/` / `prompts/` / `skills/` / `pipeline.py` / `models.py`）已成为死代码，且 `crewai` / `litellm` 依赖仅服务于 V3，持续增加构建体积与维护面。

ADR-001 曾决定（D2 / D8）保留 V3 旧 API 与业务模块，并通过 `Job.kind` 字段做 V3/V4 跨版本分发。现 V4 已稳定、V3 无前端调用方，可执行移除。

## 决策

### D1：删除 V3 后端模块与路由

删除 `backend/app/` 下 V3 专属代码：

- 路由：`api/v3/`（`/api/health`、`/api/eoicd/analyze`、`/api/jobs/*` 全部移除）；
- 业务模块：`crew/`、`merge/`、`scoring/`、`docx/`、`parsers/`、`llm/`、`prompts/`、`skills/`、`pipeline.py`、`models.py`。

删除后 FastAPI 入口仅保留 `/api/v4` 命名空间。

### D2：迁移共享 JobStatus 枚举

`JobStatus` 从 `app/models.py` 迁入 `app/job_manager.py`，作为 Job 管理的唯一状态枚举来源；删除 `models.py` 前先全仓库确认非 V3 的 `JobStatus` / `app.models` 引用已迁移。

### D3：移除 kind 字段与跨版本分派（决策点 A1）

- 删除 `Job.kind` 字段与 `create_job(kind=...)` 参数；
- 删除 `jobs.py` 的 `_ensure_v4_job`、`outputs.py` 的 kind 校验、`main.py` 的 `/api` 路由装载；
- **不**提前引入 `analysis_direction`；正向 / 反向任务类型留待后续正向功能开发时独立引入。

### D4：保留 app/v4 内早期正向原型代码（决策点 B）

`app/v4/` 内的早期正向原型（`run_forward_pipeline`、`matching/{candidate_matcher,text_matcher,unified_matcher}.py`、`prompts/forward_judge.md` 等）**保留**，仅补充「当前 Web API 未调用、供后续正向重构参考」注释；不移动、不重命名、不重构。

### D5：清理 V3 依赖

`requirements.txt` 移除 `crewai`、`litellm`；对 backend 执行无缓存 Docker 构建验证。

### D6：清理前端 V3 死组件与 API

删除 `frontend/src/components/{FileUpload,ResultView,JobStatus}.tsx` 及 `api/index.ts`、`types.ts` 中的 V3 符号；保留 `FilePreview.tsx`（V4FileUpload 复用）。

### D7：保留 backend/output/v3 历史产物

不删除既有 `backend/output/v3/` 历史产物。

## 原因

- V3 已无前端调用方，且 CrewAI / LiteLLM 依赖仅服务于 V3，移除可显著减小构建体积与维护面。
- V4 已作为唯一主线稳定运行，`kind` 字段与跨版本 404 分发失去存在意义，删除可简化 Job 模型（决策点 A1）。
- 正向原型代码虽当前未被 Web API 调用，但保留了后续正向功能重构的价值，故不删除（决策点 B）。

## 影响

- **后端**：删除 10 个 V3 模块 + `api/v3/`；`job_manager.py` 简化（去 kind）；`main.py` 仅挂 `/api/v4`。
- **前端**：删除 3 个 V3 组件与 V3 API 封装；仅保留 V4 界面。
- **依赖**：`requirements.txt` 去除 `crewai` / `litellm`。
- **文档**：`README.md`、`docs/architecture/{current-architecture,api}.md`、`docs/project/{workflow,scope}.md`、`backend/.env.example` 移除 V3 表述；新增本 ADR；ADR-001 标记 Partially Superseded。

## 替代方案

| 方案 | 不选择理由 |
| --- | --- |
| 继续保留 V3 代码与依赖 | 死代码 + 多余依赖，持续增加维护与构建成本 |
| 删除 V3 但保留 `kind` 字段 | 无第二版本时 `kind` 无意义，保留反而增加复杂度 |
| 同时删除 app/v4 内正向原型代码 | 失去后续正向功能重构的参考，违背决策点 B |

## 状态

**Accepted**（2026-08-20）。
