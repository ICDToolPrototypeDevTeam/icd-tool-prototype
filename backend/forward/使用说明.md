# EoICD → HLR 正向检查集成 · 使用说明

本工具用于检查 EoICD（接口控制文档）信号与 HLR（高层需求）之间的一致性，支持单模型（单 judge）
与多模型交叉验证（多 judge 嫁接）。本文档面向**首次拿到本工程、希望解压即用**的使用者。

---

## 1. 环境准备（一次性）

需要 Python 3.10+。推荐用项目内置虚拟环境，避免污染本机：

```bash
# 在项目根目录执行
python -m venv .venv
# Windows
.venv\Scripts\pip install -r requirements.txt
# Linux / macOS
.venv/bin/pip install -r requirements.txt
```

> `requirements.txt` 已列全部依赖（PyYAML / openpyxl / python-docx / requests）。
> 若你更想用系统已有的 python，只要它能 `import openpyxl, docx, yaml, requests`，可直接用，
> 无需建 venv。

启动脚本会自动按以下顺序选择 Python，通常**无需手动改任何路径**：

```
环境变量 PYTHON  >  项目内 .venv  >  系统 PATH 上的 python
```

如需指定解释器，在运行前设置环境变量 `PYTHON` 即可（例如 `set PYTHON=C:\path\to\python.exe`）。

## 2. 准备数据

把待检查的工程数据放到 `input/<项目名>/` 下，例如：

```
input/ams/
  ├─ *EoICD*Publisher*.xlsx      # EoICD 发布端信号表
  ├─ *EoICD*Subscriber*.xlsx     # EoICD 订阅端信号表（可缺一侧）
  └─ *.docx                      # HLR 需求规范文档
```

- 工具已内置 `ams`、`eps`、`fgmc`、`hscu` 四个项目名的识别（登记在 `common/projects.py`，
  其中 `fgmc` 仅有发布端）；用其它名字时需在 `common/projects.py` 新增一项，或在运行命令里指定项目名。
- 若 `input/<项目名>/` 下存在追溯表（`设备需求与系统ICD追溯表.xlsx`），工具会自动启用追溯过滤；
  不存在则自动回退全量，无需额外参数。

## 3. 配置密钥

本工程**不存任何真实密钥**，需要你本地创建环境文件。

### 多 judge（多模型交叉验证）—— 推荐
复制示例并填入你的密钥：

```bash
# Windows
copy 启动脚本\.env.multijudge.example 启动脚本\.env.multijudge
# Linux / macOS
cp 启动脚本/.env.multijudge.example 启动脚本/.env.multijudge
```

打开 `.env.multijudge`，每个模型一组（`model / url / key` 三行挨着）。**换模型只改对应组，
不碰任何代码**：

```
# ---- judge_A（对应 JUDGE_DS_* 三行）----
JUDGE_DS_MODEL=deepseek-chat
JUDGE_DS_BASE_URL=https://api.deepseek.com/v1
JUDGE_DS_KEY=sk-你的deepseekkey

# ---- judge_B（对应 JUDGE_QWEN_* 三行）----
JUDGE_QWEN_MODEL=qwen-max
JUDGE_QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
JUDGE_QWEN_KEY=sk-你的qwenkey

# ---- judge_C（对应 JUDGE_GPT_* 三行）----
JUDGE_GPT_MODEL=gpt-4o
JUDGE_GPT_BASE_URL=https://api.openai.com/v1
JUDGE_GPT_KEY=sk-你的openaikey

# ---- arbitrator ----
JUDGE_ARB_MODEL=deepseek-chat
JUDGE_ARB_BASE_URL=https://api.deepseek.com/v1
JUDGE_ARBITRATOR_KEY=sk-你的deepseekkey
```

> 说明：**judge 显示名（judge_A/B/C）与 .env 变量前缀（JUDGE_DS_/JUDGE_QWEN_/JUDGE_GPT_）
> 是两套命名**——前者是报告里显示的 judge 标识（改在 `multi_judge_config.json` 的 `judges[].name`），
> 后者是密钥分组名（改在 `.env.multijudge`）。两者一一对应，换模型只改变量，无需改 judge 显示名。
> 另：`.env.multijudge` **必须保持纯 ASCII**（不要写中文注释）——Windows PowerShell 5.1 的
> `Get-Content` 对无 BOM 的 UTF-8 文件按 ANSI/GBK 解码，中文注释会错位并吞掉行尾换行，
> 导致**排在中文注释之后的变量被静默合并进注释、永不生效**。

想加第 N 个模型：在 `multi_judge_config.json` 的 `judges` 里加一个 judge（写 `"model": "${JUDGE_X_MODEL}"`），
再在 `.env.multijudge` 加一组 `JUDGE_X_MODEL / JUDGE_X_BASE_URL / JUDGE_X_KEY` 即可，零代码改动。

## 4. 运行

所有启动脚本都在 `启动脚本/` 目录下。运行时会自动切到项目根目录。

### 多 judge（多模型交叉验证）
```bash
# Windows：双击或用命令行
启动脚本\run_multi_judge.bat                 # 默认用 multi_judge_config.json（真实模型）
启动脚本\run_multi_judge.bat multi_judge_config.mock.json   # 用 mock 假 LLM（免真实 key）

# Linux / macOS（Git Bash）
bash 启动脚本/run_multi_judge.sh
bash 启动脚本/run_multi_judge.sh multi_judge_config.mock.json
```

### 单 judge（单个模型）
```bash
启动脚本\run_ai.bat [项目名]          # 例如 run_ai.bat ams
bash 启动脚本/run_ai.sh [项目名]
```

## 5. mock 模式（无密钥也能跑通管线）

想先验证管线、又不想填真实 key 时：

1. 在 `.env.multijudge` 中确保有 `MOCK_KEY=sk-mock`（示例已含）。
2. 另开一个终端启动本地假 LLM：
   ```bash
   .venv\Scripts\python.exe mock_llm_server.py
   ```
   看到 `listening on http://127.0.0.1:8731` 即就绪。
3. 用 mock 配置运行：
   ```bash
   启动脚本\run_multi_judge.bat multi_judge_config.mock.json
   ```

> 注意：mock 的结论是演示性的（基于哈希伪随机），**不代表真实分析**，仅用于跑通流程 / 演示多 judge 结构。

## 6. 产物位置

- `output/`：带时间戳的 Word / Excel 共识报告、run manifest。
- `runs/integration_workspace/`：聚合中间产物（`multi_judge_aggregate.json/csv`、`multi_judge_summary.json` 等）。

### 6.1 Token 用量统计（工程集成契约）

正向多 judge 管线的 token 统计由工程侧采集，源树代码保留以下契约（同步上游时不得删除）：

1. 每次 LLM 响应后向 stdout 打印**增量**标记 `[tokens] delta=N`（父进程只做加法）。
2. identity / attribute 入口进程退出时，把本进程累计值写到
   `<output_dir>/token_usage.json`。
3. AI 映射生成进程（`--ai-update`）把本进程累计值写到
   `<judge_ws>/ai_update_token_usage.json`。
4. runner 接受 `--base-tokens`（续跑前的累计值），汇总各 sidecar 与仲裁 token 后，
   写入 `multi_judge_summary.json` 的 `token_usage`，并在结束时打印本轮 / 累计用量。
5. Word 报告头部显示「总 Token 用量」。

## 7. 常见问题

- **报 `API_KEY not found` / `未找到 .env.multijudge`**：按第 3 步创建环境文件并填值。
- **报缺包（No module named openpyxl 等）**：依赖没装进当前解释器，回到第 1 步建 `.venv` 并 `pip install -r requirements.txt`。
- **`FileNotFoundError` 带 `/c/Users...`**：这是把 Git Bash 路径直接传给 Python 导致的；用启动脚本或相对路径即可，勿手敲 `/c/...` 给 Python。
- **想换模型**：只改 `.env.multijudge` 对应组的 `JUDGE_X_MODEL` / `JUDGE_X_BASE_URL`，config 无需动。
