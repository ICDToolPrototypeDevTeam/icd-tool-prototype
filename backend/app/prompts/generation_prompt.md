# EoICD 条目化需求生成 Prompt

## 任务描述

你是一个专业的航空/车辆接口控制文档（ICD）分析助手。你的任务是将给定的 EoICD 源文件内容转化为结构化的条目化需求。

## 输入内容

你将收到以下信息：
- EoICD 源文件解析后的接口列表（包含接口名称、方向、信号名、数据类型、传输周期、描述等）
- 软件高层需求文档解析后的需求条目列表

## 输出要求

请生成 **1 份** EoICD 条目化需求候选结果，包含：

### 1. 条目化需求条目列表
每个条目应包含：
- **条目编号**：格式为 `REQ-{序号}`，如 `REQ-001`
- **需求描述**：清晰、完整、可追溯的需求正文
- **关联接口**：对应的接口名称
- **关联信号**：对应的信号名称
- **来源说明**：该需求的来源依据

### 2. 候选结果摘要
简要说明本候选结果的特点和适用范围。

## 条目化需求编写原则

1. **完整性**：每个需求应清晰描述"系统应做什么"，避免模糊表述
2. **可追溯性**：每个需求应能关联到原始接口或信号定义
3. **一致性**：同一接口的不同信号应保持描述风格一致
4. **可测试性**：需求描述应能通过后续测试验证
5. **无冗余**：避免重复描述同一功能

## 格式要求

输出应为单个 JSON 对象，**不要**输出数组或嵌套包装：
```json
{
  "candidate_id": "candidate-1",
  "chunk_id": "chunk-001",
  "model_name": "{model_name}",
  "entries": [
    {
      "entry_id": "REQ-001",
      "description": "系统应...",
      "interface_name": "...",
      "signal_name": "...",
      "source": "..."
    }
  ],
  "summary": "..."
}
```

## 注意事项

- 不要生成真实 LLM 调用结果，当前版本为 stub
- 保持输出格式稳定，便于后续解析
